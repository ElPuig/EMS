# Fixes:

## Hierarchy-managed roles (Head of Studies, Deputy, Department Chief, Seminar Chief, Secretary, Tutor, Director) could be added or removed manually, bypassing their real source of truth (issue #373):

- Reported as "the DHOS role can be removed from the teacher's form, but should not" - reproduced live with a real employee (Fernando Porrino Serrano, DHOS) and root-caused precisely, not fixed on assumption:
  - `_onchange_role_ids` (the only guard that existed) `return`ed as soon as it corrected the *first* mismatched role it found in a given call - any *other* role simultaneously out of sync (e.g. an employee who is both a Department Chief and a top-level Area Manager, with both tags stale at once) silently went uncorrected. Reproduced this exact scenario with `Form()` and a real headless-Chrome tour, for both HOS and DHOS.
  - Nothing validated `role_ids` at all when written from anywhere other than the employee form's own tag widget: `ems.role`'s own `employee_ids` reverse field (the role's "Assigned to" tab - confirmed this is how the real DHOS assignment used for the repro had actually been set, with no backing department at all), a direct `write()`/API call, an import, or a list-view bulk edit.
- Real fix, not just a UI patch: `_onchange_role_ids` now loops every one of the 7 roles via a new shared `_ems_role_hierarchy_truth()` helper (single source of truth, also removes duplicated logic) and corrects/warns for all mismatches in one pass. A genuine server-side `@api.constrains('role_ids')` (`check_role_hierarchy`) now enforces the same truth on every `write()`/`create()`, from any code path - this is the real barrier now, the onchange is UX only. `ems.role.write()` independently rejects touching `employee_ids` on these 7 roles (writing from the role's own side never reaches `hr.employee.write()` - different model, needs its own guard). A new `EMS_ROLE_SYNC_CONTEXT_KEY` context marker (same pattern as the pre-existing `EMS_PHOTO_SYNC_CONTEXT_KEY`) is the one legitimate bypass, used only by the 5 internal `update_*_role()` sync methods and by each onchange correction itself.
- UI (developer feedback after the first pass): the "Assigned to" tab on a locked role's own form now shows a role-specific explanation (naming the exact screen to actually use - department form/group form/Settings, depending on which of the 7 roles it is) instead of a generic message, and the kanban card's own delete button (a bespoke EMS addition, not native Odoo - `views/community/employee/kanban.xml`) is hidden for these roles via the standard `read_only_mode` kanban template variable, which already reflects the embedding field's own readonly. An earlier attempt (a dynamic `class` expression directly on the field) crashed the whole role form's OWL template compilation - caught by a new browser tour, not by `./upgrade.sh` or the backend suite; a second attempt (swapping in a read-only `many2many_tags` widget) worked but changed the card's visual style, so it was replaced with this native fix once its exact root cause (Odoo's own kanban `delete` attribute vs. the field's `readonly`) was found.
- The original issue also raised a second, unrelated concern (whether the Director ends up correctly at the top of the reporting hierarchy) - investigated and confirmed already correct (handled by `_compute_parent_id` once the Director is set from Settings); no code change needed for that part.
- New tests: ~10 new backend tests reproducing the exact bug scenarios (simultaneous multi-role mismatch, direct `write()` bypass, the role-form bypass) plus a new browser tour (`ems_role_hierarchy_lock_smoke`) covering the banner text and the hidden delete button, including a contrast check that a minor (non-hierarchy-managed) role keeps working exactly as before. ~30 pre-existing tests that intentionally wrote these 7 roles directly without real backing data (to test unrelated behavior, e.g. security-group sync) were updated to use the new internal-sync bypass context, keeping their original purpose intact.

# Internal changes:

## Shared role-hierarchy truth helper:

- `_ems_role_hierarchy_truth()` (`models/employees/employee.py`) replaces the same per-role mismatch-detection logic that used to be duplicated inline in `_onchange_role_ids` - now the single source of truth reused by the onchange and by the new server-side constrains.
