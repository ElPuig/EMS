# Fixes

## New student auto-placement and enrollment generation from Studies (issue #455):
- Creating a new student with the **Studies** field already set now auto-picks a Main Group (or uses the one given explicitly) and generates the subject enrollment lines from the matching enrollment template, exactly as an existing student's `study_id` change already did via `write()` (`_ems_refresh_enrollments_from_template()`). Previously this only worked when editing an existing, already-placed student; a brand-new student created with Studies set was left without a Main Group and without any `ems.enrollment` rows.
- Follow-up fix found during manual testing: the very first version of this change still skipped the refresh whenever **Main Group** was given explicitly alongside **Studies** in the same save — which is the normal way of completing the Studies tab in order (Studies, then Main Group, then Save), so it silently produced zero enrollments for the everyday case, both at student creation and when placing an existing/unplaced student (e.g. a converted applicant) for the first time via `write()`. Fixed by only excluding an explicit Main Group when the student *already had one before this save* (a genuine group change, with real old enrollments to migrate) — a true first placement has nothing to migrate from, so the template refresh now runs regardless, using the given group.
- The group-lookup logic shared by `write()` and `create()` was extracted into `res.partner._ems_auto_group_for_study()` (pure refactor of the existing `write()` behaviour, no functional change there).
- Added a real enrollment template (`AO-1`) for the PFI_AG01/AO study, which had none in this dev environment and was used to manually verify the fix end-to-end.
- Course transition, enrollment confirmation (`sale.order._ems_apply_destination_placement()`), and the applicant/student bulk-import wizards are all unaffected (verified by tracing every one of their code paths).
- New `TestContactCreateWithStudy` test class plus new first-placement/explicit-group cases in `TestContactStudyChange`, in `tests/test_contact.py`; full regression run across `TestContactLifecycle`, `TestContactFields`, `TestContactMainGroupChange`, `TestContactStudyChange`, `TestCourseTransition(Tour)`, `TestEnrollmentPlacement(Tour)`, `TestApplicantImportWizard(Tour)` and `TestStudentImportWizard(Tour)` — all green.
