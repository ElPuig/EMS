# Fixes

## Reject malformed email addresses on save (issue #467):

- Amazon SES flagged an outgoing send as suspected spam; traced back to phone numbers stored in email fields (e.g. `student_import_wizard.py`'s "phone - email" positional CSV parsing silently misassigning a value when the source didn't split as expected).
- Every place an email is stored or manually typed now validates the format with Odoo's own `odoo.tools.mail.email_normalize()` and refuses to save anything that isn't a single well-formed address (blank is still allowed): `res.partner.email`/`student_email` (`_check_email_format`, `models/contacts/contact.py`), `ems.notice.line.email` (Communications → Notices, editable inline before sending), `ems.limesurvey_recipient.email` (manually-added survey recipients), and `res.company.secretariat_email` (EMS settings).
- Validating on `res.partner` itself already covers every CSV import wizard (`student_import_wizard.py`, `applicant_import_wizard.py`, `student_update_wizard.py`) and the "Add family contact" wizard, since they all funnel into `res.partner.create()`/`write()` — a Python `@api.constrains` always runs regardless of `sudo()`. A malformed value in an import row now fails just that row (already caught and logged per-row by the wizard's own error handling) instead of being silently imported.
- Found while testing the above: `student_import_wizard.py`/`applicant_import_wizard.py`'s per-row error handling caught the exception but never rolled back what the row had already written before failing (unlike `student_update_wizard.py`, which already did this correctly) — a row reported as failed could still leave a half-created contact behind. Both loops now wrap each row in `self.env.cr.savepoint()`, so a failed row is now genuinely not applied at all, matching what "reported as failed" is supposed to mean.
