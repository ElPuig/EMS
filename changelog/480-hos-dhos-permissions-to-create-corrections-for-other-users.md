# Fixes

## Head of Studies / Deputy Head of Studies / Director can now create attendance correction requests for other employees:
- Reported by Fernando Porrino (DHOS): opening another employee's attendance record and clicking "Request Correction" failed with an AccessError ("Attendance correction: own data"), even though a Head of Studies/Deputy Head of Studies already has unrestricted read/write on `ems.attendance_correction`.
- Root cause: `role_hos` and `role_dhos` both map to the exact same `ems.group_head_of_studies` security group (there is no separate DHOS group in this codebase - HOS and DHOS have always been indistinguishable at the ACL/rule level), and that group's own record rule (`rule_attendance_correction_hos`) explicitly had `perm_create=False`, same as its `ir.model.access.csv` row. The only rule granting create rights to a member of `group_head_of_studies` was the teacher "own data" rule (inherited via `group_teacher`), restricted to `employee_id.user_id = user.id` - so in practice, before this fix, neither HOS nor DHOS (nor Director, which implies the same group) could create a correction on anyone else's behalf; only Academic Admin could.
- Fix: `rule_attendance_correction_hos` and its matching ACL row now grant unrestricted create rights, matching the unrestricted read/write the group already had. No UI/view change was needed - the "Request Correction" button already lives on the native `hr.attendance` form, reachable for any employee's attendance record these roles can already open.
- Added backend coverage: a Head of Studies user (and, separately, a Director user - confirming `group_director`'s implication of `group_head_of_studies` carries the fix through with no Director-specific rule) creating a correction for a different employee now succeeds, and a plain Teacher attempting the same for someone else's attendance is confirmed to still be denied.
