# Fixes:

## Guard duty board crashed with no "Current course" configured, and shared calendars could crash a rename:

CI surfaced two crashes on a fresh database (no dev-only state to mask them, unlike this box's own
dev DB). First: the guard duty board's client action read `current_course_id` unguarded, raising a
raw `ValueError: Expected singleton: ems.course()` instead of a friendly message on any instance
where an admin hasn't picked a "Current course" yet - a real state for a freshly installed
instance, not just CI. Added `res.company.get_current_course_or_raise()` (a friendly
`ValidationError`, reused by the working-schedule import wizard's own pre-existing check for the
same condition) and wired both of the board's RPC entry points through it. Second: renaming any
employee still on the shared company-default calendar (every non-teacher, or a teacher predating
their own personal calendar) could crash the same way if a second employee happened to share that
calendar, because `resource.calendar.get_employee()`'s reverse-search fallback assumed a unique
match. It now returns "no owner" instead of an ambiguous multi-record match, matching what every
caller already does with "no owner". Verified with the affected test classes plus the guard duty
board's own browser tour, and a clean `./upgrade.sh`.

# Internal changes:

## `views/employees/` reorganized into `views/community/` (folder mismatch with app menu structure):

`views/`'s top-level folders mirror the app's own root menu structure (`community/` = "Educational
Community", `academic_management/` = "Academic management", etc.), not `models/`'s domain folders
- a `views/employees/` folder existed only because `models/employees/` does, but no root app menu
named "Employees" exists at all: every menu item defined inside it (`non_teaching_type/`, the "My
Profile" photo-visibility form) actually resolves up to "Educational Community". Moved both into
`views/community/non_teaching_type/` and `views/community/employee/user_profile_form.xml`,
updated the manifest and one stale doc path reference, deleted the now-empty folder. Audited the
rest of `views/` the same way (full `<menuitem>` parent-chain trace plus a cross-folder model
check) - no other misplacements found. The convention itself, including which folders don't map
to an EMS root menu and why, is now documented in `CLAUDE.md`'s "Module structure" section.
Verified with a clean `./upgrade.sh` and a full, unscoped `./test.sh` (0 failed, 0 errors across
1796 tests).
