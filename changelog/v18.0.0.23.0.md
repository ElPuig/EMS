# Internal changes:

## `views/employees/` reorganized into `views/community/` (folder mismatch with app menu structure):

`views/`'s top-level folders mirror the app's own root menu structure (`community/` = "Educational
Community", `academic_management/` = "Academic management", etc.), not `models/`'s domain folders
- a `views/employees/` folder existed only because `models/employees/` does, but no root app menu
named "Employees" exists at all: every menu item defined inside it (`non_teaching_type/`, the "My
Profile" photo-visibility form) actually resolves up to "Educational Community". Moved both into
`views/community/non_teaching_type/` and `views/community/employee/user_profile_form.xml`,
updated the manifest and one stale doc path reference, deleted the now-empty folder. Audited the
rest of `views/` the same way (full `<menuitem>` parent-chain trace plus a cross-folder model
check) - no other misplacements found. The convention itself, including which folders don't map
to an EMS root menu and why, is now documented in `CLAUDE.md`'s "Module structure" section.
Verified with a clean `./upgrade.sh` and a full, unscoped `./test.sh` (0 failed, 0 errors across
1796 tests).
