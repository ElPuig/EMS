# Fixes

## Upgrades now also update EMS's installed OCA dependencies (queue_job paused its runner):
- `upgrade.sh`, `deploy.sh` (including its rollback reconciliation) and the `/deploy-check`
  dry-run only ran `odoo -u ems`, which upgrades ems and its dependants but never its own
  dependencies. `update.sh` git-pulls the OCA repos on every deploy, so their code moved ahead
  while their database side never followed. In production, a new `queue_job` release detected
  the stale schema ("database ems schema is outdated, -u queue_job required") and paused its
  job runner: every notice email stayed "Pending" for four days.
- New shared helper `scripts/odoo_modules.sh` (`ems_modules_to_upgrade`) builds the `-u` list
  dynamically: ems plus every installed module found in a non-core `addons_path` folder, so a
  newly added OCA repo is covered without touching any script. `upgrade.sh`'s own odoo.conf/psql
  parsing moved into the same helper.

# Internal changes

## Release close review (documentation consistency across merged branches):
- Convalidation developer doc and family manuals (en/ca/es) now reflect the portal "who acts"
  rule after #505/#515: whoever the centre contacts on the student's behalf, including the
  minor GEDAC applicant with no family on file.
- Staff Google Workspace developer doc updated to the shared
  `res.users._ems_link_google_signin(google_id)` helper introduced by #515.

## CI no longer skips the test suite when only the last pushed commit is docs-only:
- The "non-code-only push" detection in `ci-unit-testing.yml` diffed `HEAD~1..HEAD`, so a push
  of several code commits ending in a docs/changelog-only commit skipped the whole suite
  (PR #517 itself). It now diffs the whole push (`github.event.before..HEAD`) and always runs
  the suite when a PR is opened/reopened or the previous head can't be fetched (force-push).
- A docs-only push is also only skipped once the previous head's own CI run has finished
  successfully (the step waits for it if it's still running). Before, a CLAUDE.md-only commit
  pushed while the previous code commit was still being tested turned the PR green on a run that
  tested nothing, and would have stayed green even if that earlier run failed.

## Staff newsletter email is now on demand, covering every release since the previous one:
- "Prepara la release" no longer sends the Catalan staff newsletter, and it is no longer offered
  after delivering PR text. The developer asks for it when they choose (roughly weekly,
  mid-week); it then covers every release tag on `origin/main` newer than the last one already
  announced (a marker kept in the sending machine's Claude memory), built from those releases'
  merged PR bodies. No new tags means no email. Documented in CLAUDE.md.
