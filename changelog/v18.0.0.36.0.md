# Internal changes:

## Release integration (guard duty board branches combined):
- #605 (internal arrangements) was developed without #600, #604 and #606, so the three were combined by hand on the release branch: the guard selector of the new dialog keeps the per-guard cover count (#600), `board_assign()` keeps its `duty_id` (#606), and `_is_cover_still_needed()` and `_board_absence_row_management()` handle both a class and a guard duty.
- An internal arrangement is only ever about a class: a guard-duty row (WC, break) of the Absences table offers no arrangement (no detected options, no "described by hand" choice in its dialog), only a regular guard.
- Arrangement detection (`_is_free_for_arrangement()`) now follows #606's rule: a teacher is tied to their post by any guard duty that is not regular (`is_guard` and not `is_regular_guard`), no longer by the `GWC` code alone.
- `migrations/18.0.0.36.0/post-migrate.py` holds #543's steps (attendance group clean-up, archiving past courses), #573's (ESO subject renames) and #586's (removing the contact follows left by whoever created them) in a single `migrate()`.
- Guard duty manual screenshots regenerated on the integrated board.
- #611 (subgroups in a group's schedule) and #608 (a classroom's schedule names its groups) both changed the shared schedule grid: blocks carry both the detail line and the subgroup line (`_schedule_report_block_subgroup()`), and a classroom's own schedule shows no subgroup line, since its detail already names every group in the room.

## Fresh installations: nobody is born an attendance administrator:
- Installing hr_attendance grants its Administrator group to the user template every new account is copied from, so on a fresh installation every user saw and edited everybody's attendance, which #543's per-branch access relies on not happening. `res.users._ems_revoke_unearned_attendance_groups()`, run from `post_init_hook`, takes the Administrator and Officer groups back from whoever no group of theirs implies them for (the template included). Existing installations are untouched (they go through the 18.0.0.36.0 migration, which leaves hand-made grants alone). Found by CI, which installs from scratch.
- The mail tests of #586/#607 bring their own catchall address when the database has none (`ensure_catchall_address()` in `tests/common.py`).
