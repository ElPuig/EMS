# Document registry

The document registry is the list of every controlled document of the quality system: its code, the
version it is at, who owns it, when it is due for review and where the file lives.

**The file itself stays in the centre's Drive.** EMS does not keep a copy: it keeps the record and the
link. You go on editing documents exactly as before; what changes is that the state of each document no
longer lives only in somebody's head.

**Who has access:** quality coordination and the management team can create and edit records. The head
of studies and the secretariat can read them. Teaching staff see approved documents.

---

## Opening the registry

Go to **Quality → Documentation**. The screen opens with the **Current** facet already applied, so you
see what is in force and not every draft and superseded version. The facet is visible in the search bar
and one click removes it.

## What a record holds

| Field | What it is for |
|---|---|
| **Code** | The document's code (`PE3.01.15`). It can be left empty while the document has not been coded yet |
| **Name** | What the document is called |
| **Kind** | Procedure, record, template, strategic document, form or manual |
| **Procedure** and **Process** | Where it hangs in the process map. Fill in the procedure and the process fills itself |
| **Responsible post** | Who drafts and maintains it. A post, not a person: when somebody else takes the post over, the record stays right |
| **Version** | The version in force |
| **Approved on / Last revised on / Next review** | The dates the management review asks about every year |
| **State** | Draft, Under review, Approved or Obsolete |
| **Superseded by** | When a document becomes obsolete, which one replaces it |
| **Link** | Where the file is in Drive |

## Facets that save you work

In the search bar, besides **Current**:

- **Pending review or approval** — what is under way and not closed yet.
- **Review due** — approved documents whose next review date has passed. This is the list you need to
  prepare the management review.
- **Strategic documents** — the educational project, the functioning rules, the language project, the
  plans, with their approval dates.
- **Not coded yet** — registered documents waiting for a code.
- **Code out of the current map** — documents still carrying a code from an earlier process scheme. If
  any shows up, it is quoting a process that no longer exists.
- **No link** — records whose file address has not been filled in yet.

**Group by** shows the registry by process, procedure, kind, state or responsible post.

## Registering a document

1. **Quality → Documentation**, then **New**.
2. Fill in the name and the kind. The code can wait.
3. Fill in the procedure it belongs to: the process fills itself.
4. Fill in the responsible post.
5. Once the document is approved, set the version, the approval date and the next review date, and move
   the state to **Approved** in the top bar.

## Replacing a document with a new version

When one document gives way to another:

1. Open the old record and move its state to **Obsolete**.
2. In **Superseded by**, pick the new record.

That way any older record quoting the old code still resolves to something, which is what an audit will
ask for.
